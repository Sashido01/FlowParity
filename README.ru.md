# FlowParity

**Нативный навык Codex для разрешённого анализа приложений, самостоятельной реализации пользовательских сценариев и проверки функциональности по доказательствам.**

**Версия:** 0.0.1 · **Лицензия:** MIT · **Среда:** Codex для навыка, Python 3.10+ для необязательной офлайн-утилиты.

FlowParity **не предназначен** для копирования чужого исходного кода, бренда, закрытых API, данных или авторских материалов. Он помогает понять доступные пользовательские сценарии, создать **собственную реализацию в существующем нативном стеке** и проверить её. Не нужны API-ключи, сервер, подписка на модели или сторонние Python-пакеты.

## Возможности

- Фиксирует допустимые источники, наблюдаемые сценарии, приоритеты функций и доказательства без выдумывания поведения.
- Отделяет функциональное соответствие от копирования чужого визуального оформления.
- Учитывает существующие стеки HTML5/Node, Rust/Slint/SQLite и Windows.
- Помогает подготовить локальные тесты ошибок, доступности, приватности и сохранения состояния.
- Предоставляет небольшую офлайн CLI с командами `init`, `validate`, `cases`, `report`, `gate` для необязательного JSON-реестра.
- Завершает работу при достижении реальных критериев приёмки, не плодит новые задания и документы.

## Установка навыка Codex

Скопируйте **всю** папку `.agents/skills/flow-parity/` в `.agents/skills/` нужного репозитория. Если каталог уже существует, сравните его содержимое; не перезаписывайте изменения вслепую. В текущем репозитории навык уже доступен. В Codex явно вызовите:

```text
Используй $flow-parity: изучи разрешённый пользовательский сценарий, самостоятельно реализуй и проверь локальную версию.
```

Навык действует на уровне проекта; глобальные настройки Codex, авторизация и MCP не меняются. Автоматическое обнаружение и активацию в конкретной среде Codex необходимо проверить отдельно; здесь проведены только статические проверки навыка.

## Необязательная CLI

Утилита работает без сети и записывает файл только при `init` по явно заданному новому пути:

```powershell
# PowerShell (Windows) — из корня репозитория
py -3 src/flow_parity.py --help
py -3 src/flow_parity.py init --out task.json --name "Моё приложение"
py -3 src/flow_parity.py validate task.json
py -3 src/flow_parity.py cases examples/demo.json
py -3 src/flow_parity.py report examples/demo.json
py -3 src/flow_parity.py gate examples/demo.json
```

```bash
# Ubuntu
python3 -m unittest discover -s tests -v
python3 src/flow_parity.py report examples/demo.json --json
```

`examples/demo.json` содержит **синтетические тестовые данные** и искусственно записанное одобрение. Его успешный gate **не означает**, что реальное приложение прошло проверку. Gate оценивает только реестр и внесённые автором отметки, а не выполняет независимый аудит безопасности и не проверяет внешние файлы доказательств. Новый реестр намеренно неполный и не проходит валидацию до заполнения.

## Порядок работы

1. Проверить права на изучение источников; выбрать один локальный сценарий и ограниченную цель.
2. Зафиксировать наблюдаемые входы, результаты, крайние случаи, разрешения и ссылки на источники с датами.
3. Реализовать функциональность в существующем стеке, с оригинальными интерфейсными материалами.
4. Тестировать **локальную реализацию**, фиксировать фактические результаты, неизвестное отмечать `NOT_VERIFIED`.
5. Завершить задачу после подтверждённой приёмки. Публикация требует отдельного разрешения.

## Границы и ограничения

В проекте нет браузерного робота, генератора клонов приложений, загрузчика файлов, сравнения изображений, сборщика исходников, запуска моделей или автопубликации. Python CLI проверяет структуру реестра, ссылки и записанные подтверждения выпуска, **но не** фактическую эквивалентность приложений. Независимое тестирование функциональности в реальном приложении и активация навыка на конкретной ОС — `NOT_VERIFIED`, пока не проведены. Экономия квоты не измерялась.

Совместим с `AGENTS.md` и навыками целевого проекта. При наличии ScopeAnchor сохраняйте его существующие правила завершения задач, не создавайте второй учётный процесс.
