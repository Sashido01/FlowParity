# Установка и использование

## Нативный навык (рекомендуется)

Скопируйте `.agents/skills/flow-parity/` в `.agents/skills/` целевого проекта. При существующей папке сначала сравните файлы. В сессии Codex, открытой для проекта, вызовите: `Используй $flow-parity для анализа экспорта нашего приложения и проверки локальной реализации.` Для самого навыка не требуется Python, сервер, платный API или изменение глобальных настроек Codex.

Не считайте автоматическую активацию подтверждённой до теста на чистой сессии Codex. Если ScopeAnchor уже установлен, оставьте ему управление границами и завершением задачи; FlowParity отвечает за доказательства функциональности и QA.

## Офлайн CLI (по желанию)

Windows PowerShell из каталога исходников FlowParity:

```powershell
py -3 src/flow_parity.py init --out task.json --name "Пример"
py -3 src/flow_parity.py validate task.json --json
py -3 src/flow_parity.py cases examples/demo.json
py -3 src/flow_parity.py report examples/demo.json --json
py -3 src/flow_parity.py gate examples/demo.json --json
```

Ubuntu:

```bash
python3 src/flow_parity.py --help
python3 -m unittest discover -s tests -v
```

`task.json` — намеренно неполный шаблон. Заполните массивы, основания разрешённого доступа к источникам, ID доказательств и отметки ручной проверки до допуска к выпуску. Схему можно посмотреть в [синтетическом примере](../../examples/demo.json) и [архитектуре](architecture.md). Успешный PASS примера не означает тестирования настоящей программы.

`cases` выдаёт рекомендации тестирования только в stdout, не создавая новых файлов. Перенаправляйте вывод в существующую документацию QA лишь по необходимости. Никаких автоматизированных атак на сторонние сервисы.
