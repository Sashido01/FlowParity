# Архитектура

FlowParity состоит из **двух независимых частей**:

1. `.agents/skills/flow-parity/`: нативный навык Codex с коротким `SKILL.md`, необязательными метаданными и четырьмя тематическими справочниками, которые читаются по необходимости. Навык использует инструменты существующего проекта, а не подменяет агента, браузерную автоматизацию или систему сборки.
2. `src/flow_parity.py`: необязательная офлайн-утилита на стандартной библиотеке Python 3.10+. Читает UTF-8 JSON (не более 1 МиБ), поддерживает `init`, `validate`, `cases`, `report`, `gate`. Не использует сеть, subprocess, shell, сторонние зависимости или телеметрию. Только `init` записывает файлы, отказываясь от перезаписи существующих.

## Контракт JSON

Документ `schema_version: 1` содержит `project`, `reference`, `sources`, `features`, `flows`, `tests`, `evidence`, `review`. Связанные объекты имеют уникальные ID с префиксами `SRC-001`, `FEAT-001`, `FLOW-001`, `TEST-001`, `EV-001`.

- Основание `basis`: `owned`, `authorized` либо `public_observation`. Для разрешённых частных источников нужен комментарий о праве доступа. При публичном наблюдении нельзя заявлять закрытые материалы как свои.
- Приоритет функции: `must`, `should`, `could`; статус: `planned`, `partial`, `verified`, `blocked`, `out_of_scope`. Подтверждённые функции обязаны содержать ссылки на источник и доказательство. Обязательную функцию нельзя исключить из области без изменения требований.
- Каждый сценарий описывает шаги, ожидаемый результат, связанные функции и тесты. У пройденного теста должны быть ссылки на доказательства.
- В `review` хранятся ручные отметки о выпуске, проверке безопасности и лицензии; утилита не может подтвердить, что сами проверки проводились.

`gate` проходит, только если все обязательные функции подтверждены и связаны со сценариями, существуют сценарии и тесты, все перечисленные тесты имеют статус `passed`, а проверки и выпуск записаны как одобренные. `should`/`could` информационные. Это **проверка записей**, а не фактическое исполнение или сертификация. Ложные записи могут привести к PASS, поэтому независимая проверка обязательна.

## Коды завершения

`0` — успешное выполнение (включая информационный `report` для заблокированного выпуска), `2` — некорректный ввод/ошибка файловой системы, `3` — валидный, но заблокированный `gate`.

Реализация следует стеку и журналам целевого проекта; создавать параллельный источник истины не требуется. См. [Использование](usage.md), [Безопасность](security.md).
