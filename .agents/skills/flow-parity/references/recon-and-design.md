# User-journey reconnaissance

Minimize discovery: begin with the core job-to-be-done, platform, audience, permissions, current project behavior and one representative flow. Record:

- Screen inventory: route/state, accessible role, user intent, transitions and privacy boundaries.
- Per-flow input, output, error, empty/long/Unicode state, loading, persistence, simultaneous use, recovery, and keyboard accessibility where applicable.
- Functional must/should/could priorities with reasons. Separate observed from inferred features; do not represent missing evidence as certainty.
- Design as information hierarchy, component behavior, accessibility and roles rather than pixel-perfect identity; choose original assets and visual identity.
- Engineering context: native existing stack, tests, state model, data migrations, supported operating systems.

For each observation preserve source link/path and date. Public pages may change. Keep screenshots local unless permitted. Do not automatically rewrite the host project's architecture to match a reference app.

A valid reconstruction outcome is not necessarily identical appearance; prioritize reliable, accessible, independently implemented behavior.
